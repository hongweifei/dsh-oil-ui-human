# 动效规范

## 界面应有基本动效

完全静止的界面如同一张截图：按下没有回应，切换没有来路，用户只能猜测刚刚发生了什么。新建界面以及改动了操作流程的界面，应优先覆盖以下几处：

1. **主操作的反馈。** 按下后立即产生回应，完成时给出一个结果：按钮下沉后回弹，勾选符号被绘制出来，数字滚动至新值。
2. **一处状态切换的去向。** 选中、展开、切换视图、增删列表项时，应使人看清元素从何而来、往何处去，详见下文"界面过渡"。
3. **首次进入时的一次出场。** 主角先出现，其余按阅读顺序依次跟上，且仅在首次进入时播放。

这些之外再增加的动效，应能说明它承担反馈、引导、连续性或品牌表达中的哪一项；说不清职责的动效容易沦为干扰。

| 目的 | 适合考虑的实现方式 |
| --- | --- |
| 按下、聚焦、展开或一般性的状态变化 | 使用浏览器原生的过渡，或已有组件自带的小型过渡 |
| 视图之间的切换、元素位置变化 | 共享元素过渡，详见下文"界面过渡" |
| 拖拽、手势、位置与大小的变化、多个元素协同的动画 | 使用项目中已有的成熟动效库 |
| 特殊品牌画面、材质、复杂物理效果 | 图片、三维渲染、着色器或预渲染视频，按需求取舍；何时使用实时 3D 参见 [素材指南](media.md) |
| 使用鼠标、触控或滚动控制一段叙事的进度 | 让动画进度直接跟随输入变化，回滚和快速操作均需妥善处理；详见 [滚动叙事](scroll-narrative.md) |

需要精确控制状态的界面，应以代码编写动画；画面变化内容早已确定的，可以使用生成的视频。用于展示实时数据、需要供人实际操作的控件，不能用视频替代。

## 手感

动效的手感应从设计方向的材质与调性推导得出，并使用"动作加实物"的方式命名和选择参数（弹簧刚度 / 阻尼）：

| 动作 | 实物参照 | 刚度 / 阻尼 | 适用场景 |
| --- | --- | --- | --- |
| 咔嗒 | 磁铁吸合、卡扣、拨动开关 | 350–400 / 10–15 | 按钮、开关、下拉展开 |
| 滑入 | 气压闭门器、抽屉阻尼 | 250–300 / 20–25 | 底部面板、抽屉、折叠 |
| 流淌 | 倒蜂蜜、雾气弥散 | 150–200 / 30–40 | 页面转场、主视觉出现 |
| 砸落 | 锤击、重物落桌 | 400–500 / 5–10 | 确认选择、完成反馈 |
| 回弹 | 橡皮球、蹦床 | 300 / 8 | 庆祝提示、儿童与游戏类产品 |
| 漂浮 | 氦气球、飘絮 | 100 / 25 | 冥想、梦幻场景、空闲循环 |

厚重的材质（石材、金属、陶瓷）偏于咔嗒和砸落，轻薄的材质（纸张、布料、雾气）偏于漂浮和流淌；高频操作使用短促的动作，少见的品牌时刻才使用绵长的动作。喧闹粗粝的设计方向可以采用硬切、80–150ms 的线性跳变和抽帧，作为有意的品牌表达。

过冲幅度应随元素面积变化。整页、面板这类大面积元素，过冲不应超过 1–2%，否则整块画面会产生晃动；徽章、勾选标记这类小元素可以过冲 10–20%，以呈现弹性感。表中阻尼偏低的参数仅用于小物件。

网页可将弹簧写成缓动曲线：按刚度和阻尼对位移进行数值积分，取 20–30 个采样点写入 `linear()`，时长取位移稳定在终点 0.5% 以内的时刻。不支持该语法的浏览器退回相近的 `cubic-bezier`。

## 呼应：使动作彼此衔接

一个动作引起的变化应沿同一条路径传递下去，前一段的终点即下一段的起点；不要让按钮、面板和数字各自动作。

- **从被操作之处出发。** 点击"加入购物袋"，商品缩小为一个点飞入购物袋，袋子上的数字随之跳动；删除一行时，它向删除按钮的方向收走，下方的行补充上来。
- **一次切换只朝一个方向。** 卡片向左滑动，标题、序号和底色也向左更替；数字向上滚动，进度也向上涨。方向混乱，就会变成几段互不相干的动画。
- **主角先动，其余被带动。** 被影响的东西延迟 40–80ms 跟上，幅度更小，如同被主角牵引过去。全部同时起步、幅度一致，看起来只是一同闪了一下。
- **形状接力。** 上一状态中的元素转变为下一状态中的元素：按钮展开为面板，搜索图标拉伸为输入框，播放键变为暂停键。用户一眼即可识别它们是同一个对象。
- **动法与画面属于同一种材质。** 动作的轻重、停顿和回弹应从方向卡的生成引擎与控件语法推导得出。

### 巧妙之处应从产品中寻找

巧妙之处是让一处动效讲述这个产品自身的故事，而不是增添更多花样。应当写成一句话：这个产品里的哪一样东西，因为用户的哪一个动作，发生了只有它才会有的变化。

找不到这样的动作时，把基本动效做准确即可，不要勉强虚构。巧思贵在有效而非数量，其余动效保持安静、短促。

## 界面过渡

**保持连续性。** 用户点击的对象就是下一屏的主角。从列表进入详情时，被点击的那一项放大为详情视图，其他项淡出；返回时它缩回原位，页面回到原来的滚动位置。若原位已经不在视口内，应先将其滚动至可见区域，再执行缩回。

**方向保持一致。** 下一项从右侧进入，上一项从左侧进入；打开与关闭互为逆过程；侧面板从其所在的那一侧滑入滑出。方向随意的动画比没有动画更加令人困惑。

**只变换形状时不做交叉淡化。** 切换视图、应用筛选、展开说明、缩放等变化中，内容仍是同一个对象，只是尺寸和位置发生了改变。应让外框直接变形，内容立即显示新状态。交叉淡化会使新旧两张缩放不同的画面叠加在一起，产生重影。只有内容本身发生更换时，才使用淡入淡出。

**离开、加入、留下分开处理。** 被移除的元素淡出，新加入的元素淡入，保留的元素滑动至新位置。三者若使用同一种淡化方式，列表就会整片闪烁。

**选中指示使用一块移动式的滑块。** 分段控件、标签页、列表当前项，均使用同一块底板滑动至新位置，而不是让旧项熄灭、新项点亮。选项宽度不同时，宽度一同过渡。首次显示、窗口缩放和字体加载完成后应直接放置到位，不要从 0 宽度生长出来。

**先准备好目标位置。** 目标页面需要加载的内容（例如图片或内嵌页面）应先完成加载或预先渲染，否则动画会停留在一块空白屏幕上。需要来回切换的视图应预先渲染并保留在页面中，切换时只做位移，不重新加载。内容加载完成后再淡入，不先闪一下白底。

**离开快于进入。** 退出时长约为进入时长的 60–70%，使用加速曲线；进入使用减速曲线或弹簧。

**到达边界要有反馈。** 已经是第一项或最后一项时，应有轻微的顶动反馈（往返 10–15px），而不是毫无反应。

### 整页转场的稳定性取舍

整页切换与组件过渡不同：旧页面需要卸载，新页面需要挂载。按稳定性与实现难度，分为三类：

- **遮罩式（Curtain / Wipe）。** 使用一块纯色、纹理或几何形状划过或覆盖整个屏幕，在被遮挡期间卸载旧页面、挂载新页面。这是最简单、最稳定的方式，两个页面的结构互不相关，绝大多数页面均适用。
- **交叠式（Overlapping）。** 新旧两页同时存在于屏幕上，相互错开、推挤，或分层淡入淡出。视觉上连贯，但两页的 DOM 需同时存在，层级和内存都须妥善管理。
- **共享元素式（Shared Element）。** 一个关键元素从旧页面持续变形至新页面，例如缩略图放大为详情页的主图。视觉上最为顺畅，也最容易出现问题：用户快速双击、中途打断、后退，或视口发生变化，都容易造成错位和闪烁，因此必须预留退路，出现问题时直接显示到位的状态。

首次进站的加载页（Splash），可以在等待大文件加载期间展示一小段叙事或进度；站内的页面跳转，时长参照下文"时长和幅度"中整页切换的取值，不要让转场遮挡用户查看内容。

## 时长和幅度

| 对象 | 时长 | 要点 |
| --- | --- | --- |
| 按下、开关、选中指示 | 150–300ms | 按下缩小至 0.96–0.98，按下时立即生效（约 80ms），松开后回弹 |
| 下拉、气泡、提示 | 180–250ms | 从触发点方向展开，缩放从 0.96 左右开始，不从 0 开始 |
| 面板、抽屉、侧栏 | 250–400ms | 按移动距离取值，距离越远时长越长 |
| 整页或视图切换 | 350–500ms | 超过 500ms 会产生等待感 |
| 首次进入时依次出现 | 每项间隔 40–80ms | 总时长不超过 600ms；仅在首次进入时播放，重新渲染和恢复状态时不重播 |

本表适用于界面操作。游戏和抽奖的演出时长参见 [游玩设计](play.md)。

悬停时上浮 2–4px，阴影随之加深。位移超过 20px 的悬停效果会显得轻浮。

## 不可见的结果应当说明

一次点击产生了不可见的副作用（例如复制到剪贴板、后台保存、发送），应使用一条短暂的提示说明结果本身，例如"已复制：……"，而不是只说"成功"。确认类的时刻（例如选中或完成）可以使用一次小幅弹出，且仅在状态首次发生变化时播放，重复点击不重播。

## 体验与性能

项目中已有的动效节奏和组件能力应先予沿用。高频执行的操作，反馈必须立即给出，不要让动画拖慢操作本身。

动画应能够被打断。连续快速操作时，新动画应从当前位置继续执行，不跳回起点重播。CSS 过渡会从当前值重新出发，适合高频切换；关键帧动画会从头重播，适合一次性的出场。业务状态应立即更新，不等待动画结束。

网页上连续播放的动画，应优先只改变换和透明度属性，过渡声明中只写会发生变化的那几个属性；很小的指示块可以直接过渡宽高。每一帧都要执行的代码，必须具备停止和清理的条件，不应交替读取布局和写入布局；滚出屏幕或无事可做时应停止执行。整页过渡期间页面通常无法点击，因此整页过渡应当简短。

存在明显位移、缩放或滚动特效的位置，须照顾开启了"减少动态效果"的用户：此时所有状态直接到位，内容一项不少。必要的信息和主要的操作，不能等待自动播放、声音或动画播完才出现。

## 检查动效

按正常速度操作一遍，再反向操作一次、快速连续点击几次：不应出现重影和跳动，元素不应突然出现，不应从异常位置飞入，不应卡在中间状态。开启"减少动态效果"后内容应直接可读。只有经过实际测量后，才可报告帧率或性能改善。

## 网页实现提示

- 浏览器原生的视图过渡适合处理"同一对象从一处变换到另一处"的情形：为前后两个状态中代表同一对象的元素赋予同一个过渡名称，该名称在同一时刻必须唯一。
- 只变换形状的过渡中，隐藏旧快照、直接显示新状态，即可避免重影。
- 过渡伪元素后面只能跟随少数伪类，例如 `:only-child`；写成 `:not(...)` 会使整条规则失效。需要按场景区分规则时，在根元素上添加一个属性用于切换。
- 内嵌页面和图片在过渡中会被截取为快照；目标尚未加载完成就开始过渡，会以空白收场。
