## 首先确定图像承担的职责

素材是设计的起点，而非布局完成之后填入的装饰。首先应回答：如果只保留一张图、一个标题和一个动作，哪张图值得占据这个位置？然后再决定是否需要更多模块。

- **区分差距来源。** 判断问题源自信息与构图，还是确实缺少一张能够表达产品与品牌的图像。不通过堆砌更多图片、光效和动画来掩盖层级问题，也不因为代码易于实现就以通用渐变和几何形状替代必要的图像。
- **为每张图界定一项任务。** 它用于展示对象、解释关系，还是建立品牌与情绪；要使人一眼看懂什么。无法回答时先不要寻找图像，也不要生成图像。图像已经表达清楚的内容，文字不再重复。
- **后台和工具同样需要判断。** 对象缩略图辅助识别，内容封面支持浏览，地图或空间图帮助定位，示意图解释关系；它们可以是界面中最有价值的部分。纯数据任务确实无法从中受益时，保留清晰的数据表达，不强行加入气氛图。
- **图像依据北极星确定，页面再与图像呼应。** 主体、视角、尺度、光线、颜色、材质和留白由设计北极星决定；页面的字体、背景、边缘处理和运动从这张图建立呼应关系，也可以使用一处受控的反差突出主动作。同一组图像应统一主体尺度、视角、光线和边缘质感，而不是给所有图像套用同一个滤镜。
- **图像是结构的一部分，而非装在盒子里的插图。** 可以让它跨越版面的分界、占满首屏，或者与文字叠加，具体做法参见"使图像与页面融为一体"。
- **先放入真实页面查看一轮，再扩展至其他区域。** 素材未到位时，占位版本所通过的审美评审不能视为最终通过。

## 复用、生成还是交由代码实现

- **有合适的即复用。** 实际查看过图像之后再引用其特征；已有优质素材时应围绕它进行设计，不为证明使用了工具而重复生成。
- **没有则制作出来。** 没有合适的现成素材、且宿主能够生成图片时，应主动制作关键素材，不因正在编写前端代码而省略这一步。需要生成或编辑图片时用 `oil_ui_image`（支持 `mode: "generate"` 文生图、`mode: "edit"` 传入 1–16 张本地参考图做同模多材质变体、以及 `background: "transparent"` 透明底抠图）。除主产品本身之外，还可以将产品所处的地域环境、原材料肌理和工序细节一并纳入这套画面，使页面具备完整的上下文，而非只放置几张孤立的棚拍白底图。需要真实材质、设计器物、历史摄影、工程测绘图、古地图、科学版画或航空航天实拍素材时，使用 `oil_ui_media` 从 Poly Haven、Wikimedia Commons、各大博物馆开放馆藏（含日本国立博物馆与国会图书馆）、LOC、Wellcome 和 NASA 检索并下载到本地 `assets/` 目录。授权不允许在页面中使用的条目同样有其价值：下载到不上线的目录，作为生图参考图，汲取其题材、年代、构图和材质线索，但不让生成结果复刻原图。编号拉取、贴图直链、联系表和视频 poster 的命令见 [工具指南](tools.md#检索和下载真实素材)；下载自动生成 `SOURCES.md`，据此保留条目许可与署名信息。
- **需要随操作实时变形的实物，采用多层次矢量或实时渲染配合静态图像。** 遇到选配器、规格切换、剖面拆解这类必须随用户点击即时改变比例、部件或色泽的区域，若只放置一张不会变化的静态照片，操作与画面就会脱节。静态图像应留给氛围、地域和材质特写；需要实时联动的主体使用内联 SVG（画足外轮廓受光体积、结构连接件和表面肌理三层细节，不画成单薄的纯色图标）或 Canvas/3D 绘制，使每一次切换都在画面上即时兑现。
- **文字和界面交由代码实现。** 文字、按钮、表单、数据标签和常规布局一律由真实 HTML/CSS 排版，不让生图模型绘制，也不以完整截图冒充可交互的成品：生图模型绘制文字容易出错、无法修改，也无法被选中和读屏。图片只负责物体、材质和光影。
- **无法制作时留下简报。** 断网且不具备生成能力时，用多层次矢量把核心对象和剖面画清楚，并附一份素材简报。不自动安装工具、切换收费服务，或要求用户把密钥粘贴进对话。
- 需要旋转、具备物理特性或随视角变化的对象参见"实时 3D"；预先确定的连续变化参见"生成视频的可选路径"。

## 使图像承载语义

生成图像最常见的失败不是画得不好，而是画得太满：细节越丰富越像图库照片，放入版面后没有重点，也和页面没有关系。

与产品无关的"好看场景"放入版面只会喧宾夺主；处处画满细节，等于没有重点。绘制实物或真实场景时，应把主体的质感和光影做足，背景和置字区域保持干净；绘制抽象功能或前后变化时，可以把大面压成单色、白模或失焦，只让关键的几处呈现颜色、光或细节。

选择能够与页面"衔接"的主体：

- 能够跨越两块色面分界的单个物件。
- 能够延伸出画面的线状物。
- 能够在其上标注的空间：模型、地图、剖面、平面图。

这类主体之后能够和页面中的线条、标注和区块连成一体；一张自给自足的风景照做不到这一点。

## 提示词撰写规范

按固定顺序撰写，每项一至两句话：

1. **主体与表现形式**：什么东西，采用什么体裁呈现（照片、插画、模型或图解），体裁从页面的方向推导。
2. **构图与留白**：主体在画面中的位置和占比，哪一块留空供文字使用。按已选的首屏骨架写出主体所在的区域和占比，以及留给文字的那一块必须完全干净。留白区不应有高光、反光或杂乱纹理，以保证文字清晰易读。
3. **安全距离**：主体、托台与阴影不要贴近文字边缘，留出 10% 左右的空隙，防止屏幕变窄时文字压到物体上。
4. **背景**：直接写出页面实际使用的十六进制色值，或者要求纯透明背景。色值一致时边缘自然融入网页，无需额外使用 CSS 遮罩修正。
5. **材质与光**：主光方向、辅光、质感。同一页面的多张图像使用同一光向。地面反光向留白侧自然衰减，不横扫至文字区域。
6. **排除项**：不要任何文字、标志、伪代码、界面截图或多余漂浮物；小件图标或透明图注明"不要地面投影"，外部投影交由前端 CSS `filter: drop-shadow(...)` 控制。

## 生成后放入页面再次判断

应在真实页面、真实尺寸中查看，不在图片查看器中判断。单独观看很好的图像，放入版面后常常主体太满、朝向不对、留白位于错误的位置。

不满意时修改提示词重新生成，并写清修改内容，例如"主体向右移动，左侧留出一半空间""去除地面反光，背景替换为页面色值"。不要围着一张不合适的图像改版式。同一批中选取最适合排版的张，不选取细节最多的那张。

## 使图像与页面融为一体

**背景融合。** 需要融入背景的主视觉和大图，不加边框，也不关闭在圆角卡片内：从图像四角实际取色，页面背景使用同一色值，或使用 CSS 遮罩、导出渐隐把四条边淡出至背景色。纯色背景时，提示词中的底色与网页一致，边缘即可自然衔接。

**透明图像。** 先放置于最终背景上检查边缘、白边和残留的棋盘格；检查透明通道应查看像素，不能依据文件后缀判断。阴影不烘焙在图像内，由页面按实际背景添加投影，这样更换背景后依然正确。

**跨越结构。** 将透明物件放置在两个色块或两个区块的分界线上，使其同时属于两侧。

**图像与代码接力。** 生成图像负责代码难以实现的材质和光，例如金属、玻璃、模型、光影。代码负责需要精确、可编辑、会延续的部分，例如从图像中延伸出去的线、路径和标注。如果图像中有一段本应延续到页面的部分，就将其裁切，改用矢量继续绘制。这样它能够准确穿过版面、带上真实文字，并在不同宽度下重新走线。

**标注。** 在图像上标注时使用细引线加文字，不使用带底色和阴影的气泡卡片。引线端点须对准图像中的真实位置：图像在版面中使用固定的尺寸和位置，按图片像素换算坐标。窄屏上隐藏标注，或改为图像下方的列表，避免它们漂移到错误的位置。

**窄屏裁切。** 不把整张大场景等比缩小至无法辨识。从原图裁出焦点区域另存一张供窄屏使用，或使用对象定位对准焦点。桌面和手机两种裁切，都必须保住承载信息的关键区域。

**一张图像多次使用。** 结尾或其他区块可以使用同一张图的局部特写，这比再生成一张光线和风格不匹配的图像更为统一。

## 以一幅画作作为舞台

另一种用法恰好相反：图像不传递信息，只提供氛围，界面保持黑白克制，全页仅使用一幅有笔触的画作作为唯一的颜色来源。

- **画作作为舞台，界面在其上演示。** 将真实界面的简化版本置于画上，画作从四周露出。滚动时画作固定不动，只更换前方的界面内容，可与"滚动叙事"衔接。
- **大胆裁切。** 只保留画作的一角或一个局部，接近抽象，不与界面争夺注意力。题材不必与产品字面相关，但气质必须相符。
- **松与紧互相衬托。** 画作越松弛，界面越要精确、干净；两者同时出现，彼此都更好看。
- **控制使用频次。** 一幅画贯穿全页，或者只在两三处出现，例如价格卡的顶端和页脚；不要每个区块都配一张。同一页面的画作应统一画种和笔触。
- **演示使用简化后的真实界面。** 次要内容虚化或替换为骨架，只把要讲述的那一处做得清晰；数字对比直接用界面元素表达，例如两条长短不同的进度条，而不是另做一张图表。

## 异质素材的单色化统一

引入历史画作、雕像肖像或外部摄影素材时，彩色位图容易与界面的主题色产生冲突。可以通过统一的单色处理将不同来源的素材收拢到当前方向之中：

- **单色映射**：将素材转为黑白高对比后，把暗部与亮部映射到页面的主色与底色。
- **网点与点阵抖动**：对写实图片进行半色调网点化或微弱的扫描线处理，消解照片的写实质感，使其能够与排版、网格共处。

## 抽象技术的主视觉推导

缺少产品截图时，不回退到通用的彩色发光球或大渐变。应从产品处理的对象中找一个有形的实体：它读写的数据呈现什么形态，它替代的那件工具或那道工序是什么，它的用户手边有什么。表现形式须满足两条：大面积色阶平稳，文字压得住；画面中的线和标尺能够由 SVG/CSS 继续绘制。找不到有形对象时，主视觉交给排版本身。

## 成套素材：角色、道具与图集

游戏、收集和养成类产品需要的不是一张配图，而是一整套会被反复摆放、翻转、比较的素材。

- **先撰写风格说明。** 画法、视角、光向、材质、比例和色板各写一句，同一批的提示词都依据它撰写。
- **同系列靠轮廓区分。** 统一比例和光向，用耳朵、道具、配饰这类轮廓特征区分个体，不只更换颜色。缩至实际显示尺寸后仍需一眼可分。
- **多状态从同一张图派生。** 生长阶段、正反面、开壳前后、不同动作，以第一张为参考图编辑出变体，保持是同一个角色；各状态的落地点对齐至同一条基线。
- **透明图集按轮廓裁切。** 格子之间保留透明间距，按实际轮廓裁切，不按格子均分，否则会切掉树冠、带进邻格的残片。检查 alpha 像素，不看预览图的背景色，再放到最终背景上查看边缘。
- **贴到物体上须两面成立。** 会翻转、落下或转到侧面的素材，正面背面都要具备，边缘沿轮廓闭合。受光交给场景处理，不在图内烘焙与场景方向相反的光影。

## 真实贴图与科学、工程素材

通过 `oil_ui_media` 的 `sheet: true` 生成的联系表 PNG 进行挑选，`imageUrl` 用于下载；`look` 中的四边色彩、纸底和干净区域，直接对应下文的背景融合、正片叠底和压字位置。Poly Haven 的 `textureMaps.diffuse.url` 是表面颜色贴图，`roughness` 和 `normal` 分别供实时材质的粗糙度与法线使用；渲染球和模型预览图不适合重复铺贴。

- 使用 Diffuse JPG 做 CSS `background-repeat: repeat` 或 SVG `<pattern>`，在最终尺寸下检查四边接缝和重复频率。部分素材仅沿一个轴重复；不要只看缩略图就认定双轴无缝。
- Three.js 的颜色贴图使用 sRGB，粗糙度与法线使用线性数据；本工具选择 OpenGL 法线，按模型 UV 和实际光照检查方向。重复材质需设置两个轴的 RepeatWrapping；模型 glTF 依赖清单中的 UV 贴图专用于该模型，不能当作无缝材质使用。
- 测绘结果只选 LOC hh 的图纸资源，照片、调查说明与图纸分开查看。地图与版画的 IIIF 原图尺寸、下载尺寸可能不同，以下载输出的宽高判断能否承载页面放大和标注。
- NASA 视频检索应排除标题或关键词明确标注为动画、仿真或可视化的条目，选定后仍要观看以确认是否符合实拍要求。首帧 poster 是静态回退方案；背景播放、循环与裁切先在真实页面中检查。
- 许可证跟随素材记录管理。Poly Haven 输出 CC0 与信源署名，Wellcome 保留条目许可；LOC 不推定所有条目无版权限制。Met、AIC、Cleveland 和 Rijksmuseum 只取公有领域或 CC0 条目；Japan Search 只取 CC0、公有领域、CC BY 和 CC BY-SA，ColBase 的图须按其要求标注"出典：ColBase"；Commons 按每个文件各自的许可执行，BY-SA 改色或合成后须以同样许可共享。V&A 的公开 API 可访问高清图，但公开访问不等于取得首页、商业用途或高清发布授权，因此标注为 `reference`。NASA 使用条件保留第三方署名与限制。官方条款随 `SOURCES.md` 一并保留，需要展示署名时置于页脚或项目的素材说明之中。

## 实时 3D

三类情形使用实时 3D：用户需要转动、检视的对象；堆叠、碰撞、推挤、摆动这类物理表现；玻璃、金属、透明塑料这类随视角变化的材质。一张生成图像即可表达的，或者仅仅为了显得高级，都不使用。

- 使用 three.js 这类成熟引擎，需要物理时再配备一个刚体库。生成的图像作为贴图、精灵或环境光来源使用，代码负责空间、运动和受力。
- 验收以画面为准，而不是以是否使用了库为标准：静帧应看得出体积、透视、接触阴影和材质区分；录屏中运动应连续，力能够传递到被推动的物体上。
- 新建的小样应将库下载到任务目录的 `vendor/` 并附许可证，不引用 CDN；存量项目按项目已有的依赖方式引入。以模块方式引入的页面和贴图要通过本地服务器打开；要求双击即可打开时，打包成一个普通脚本，贴图内联或置于同目录。
- 设备像素比上限取 2；页面隐藏或滚出视口时应停止渲染帧；无法获得 WebGL 时显示同一场景的静态图；开启减少动态效果时照常计算结果，只关闭镜头晃动和装饰性演出。
- 截图前须确认画布确实绘制出了内容，参见 [工具指南](tools.md)。

## 生成视频的可选路径

需要一段能够叠加在页面上循环播放的素材时，先检查三项：首尾能否衔接，主体的边缘是否干净，背景处理得如何。在单色背景上生成再抠像，只是可以尝试的方法之一：透明和反光的物体抠像后可能丢失边缘，或者带上背景的颜色，必须放到最终的页面背景上查看。

需要把几段视频连成一段叙事时，可以用前一段的最后一帧作为下一段的第一帧，或者事先把各段的关键帧统一规划。播放进度由滚动或手势控制时，要检查跳到任意一帧、倒序播放、加载速度和内存占用，不要默认把整段视频解码为一张张大图。

玻璃、水晶这类需要折射或透光的物体，应先在最终页面的背景色上生成画面，让折射和投影烘焙进素材，再使用视频抠像模型去除背景。直接在绿幕上生成再抠像，折射会带有绿色。预渲染的折射和光照只对应生成时的背景，不应承诺会随任意页面内容产生实时物理效果。

透明底的视频与图片一样，可以跨越在两个区块的分界上，做法见上文"跨越结构"。

## 文件与说明

- 按显示尺寸的 2 倍导出，不直接内嵌原始大图。不透明的图像使用 JPEG 或 WebP，透明的使用 WebP 或 PNG；单张控制在几百 KB 以内。内嵌为 data URL 后体积会再增大约三分之一。
- 保留提示词、原图和处理后的版本，写清每张图的来源、用途和处理方式，区分复用、裁切、生成和后处理。
- 生成图像和替代素材不得冒充真实产品截图、真实场所、真实人物或产品证据。
